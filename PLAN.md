Сегмент: ООО на УСН «доходы» < 20 млн ₽. Срок MVP — октябрь 2026.
Продуктовая рамка: **«пульт спокойствия»** (не рабочее место бухгалтера).
Полный контекст — в памяти проекта (`ob-outsource-*`), референсы — в `references/`.

## Что зафиксировано по задаче (вводные этой итерации)

1. **Продукт снимает рутину и бОльшую часть работы с клиента.** Клиент хочет знать
   *результат*: как посчитали налоги и произведены ли платежи. Деталями не грузим —
   показываем итог, а не начисление.
2. **Ключевой вопрос сейчас — как весь объём данных ложится в интерфейс.** Есть график
   всех платежей (придёт отдельным сообщением). По нему строим прототип: как клиент
   видит **поток событий в разных временных горизонтах — месяц / квартал**. Цель —
   найти лучшее представление, чтобы не перегрузить.
3. **Разделение ответственности:** клиент в бОльшей степени только **уплачивает налоги**;
   **отчётность сдаём мы**. Иногда просим клиента что-то догрузить. → В интерфейсе
   «что от клиента» (оплата, изредка догрузка) отделяем от «что делаем мы» (фон/итог).

## Жёсткие правила (не меняем)

- **Все компоненты и токены — только из DS** `/Users/tochkamac/Downloads/Прототипы/design-system`
  (алиас `@ds`). Никакого хардкода. Чего нет — расширяем DS, не хардкодим в прототипе.
- **Свой верхний навбар не делаем** — экосистемная шапка Точки это данность платформы.
  Навигацию строим от контента Главной (левый `NavigationBar` DS + контентные вкладки).
- **Не сваливаем задачи в одно ведро** (антипаттерн текущей Точки: виджет «Задачи» +
  оверлей «Уточните информацию»). Разносим по типам/разделам.

## Что оставлено как нейтральный каркас (в `src/`)

- Конфиг сборки: Vite + React 18 + react-router, DS через алиас `@ds`.
- Оболочка: `RootLayout` (экосистемная шапка + присутствие бухгалтера, сквозные),
  `PageShell` (левая колонка + контент), `EcosystemHeader`, `AccountantPresence`.
- Нейтральный UI: `Card`, `lib/format`.
- `HomePage` — пустая заглушка до графика платежей.

## Что прототип должен доказать (гипотезы, без изменений)

1. **Дефлекция + доверие** — самоочевидный статус + прозрачный расчёт → не идти в чат.
2. **Читаемость объёма** — за секунды понятно, сколько и когда платить в реальном
   периоде (весь ритм, не «раз в квартал»).

## Прогресс

- [x] Получен график всех платежей (налоговый календарь ООО, директор с зарплатой).
- [x] **Горизонт «Квартал»** — представление потока событий собрано (`src/features/quarter`):
      свод квартала (осталось уплатить · прогресс · ближайший платёж) → лента по месяцам;
      совпадающие по сроку платежи (28-е) бандлятся в одну карточку с раскрытием;
      травматизм помечен «в СФР, мимо ЕНП»; оплаченное приглушено, ближайший срок акцент;
      отдельная тихая полоса «Что делаем мы за вас» (отчётность/уведомления бухгалтера).
      Переключатель горизонта Квартал · Месяц. Всё на компонентах/токенах DS.

- [x] **Горизонт «Месяц»** — операционный экран «что от меня сейчас» (`src/features/month`):
      компактный свод месяца → герой «Ближайший платёж» с «через N дней» и CTA «Открыть платёж»
      → единый таймлайн месяца с маркером «Сегодня» (прошедшее оплачено сверху, предстоящее снизу)
      → полоса «Что делаем мы за вас в этом месяце». Строка платёжного момента вынесена в общий
      `src/features/payments/MomentRow` (переиспользуется кварталом и месяцем).

- [x] **Правило «только суммы к уплате, без прогнозов».** У суммы есть жизненный цикл:
      *ещё не посчитана* (период/расчёт не закрыт) → *к уплате* (посчитана) → *оплачено*.
      Пока сумма не сформирована — показываем состояние «Рассчитаем к сроку», а не число.
      Реализовано в общем `MomentRow` (состояние `paid | due | pending`).
- [x] **Экран «все платежи клиента за квартал» в 2 снимках времени** (`src/features/scenario`,
      данные `src/data/scenarios.ts` — I квартал 2026):
      «Середина квартала» (25 фев) — налог УСН и не закрытые периоды без сумм («Рассчитаем к 25 апреля»);
      «Конец квартала» (25 апр) — квартал закрыт, все суммы к уплате, УСН 125 000 ₽.
      Свод показывает только твёрдые «к уплате» + честную приписку «ещё N рассчитаем к сроку».

- [x] **Сценарий «Уплата налогов в августе» по драфту заказчика** (Figma `82:62589`,
      `src/features/august` + `src/data/august.ts`): **единый список платежей без разбивки
      по месяцам**, хедер-сумма + вкладки «К уплате / Готово», предупреждение о просрочке
      («2 платежа просрочено»), иконки-категории у строк (травматизм — красный, в СФР),
      плитки разделов (Операции/ЕНС/Сотрудники/КУДиР) и ссылки (PageAction). «Сегодня» — 16 авг.
      Старый месячный `ScenarioView` + `scenarios.ts` удалены (разбивку по месяцам убрали).

- [x] **Тумблер «Снимок квартала»** на экране августа (`AugustView` + `august.ts`):
      «Середина квартала» ↔ «Квартал закрыт». Демонстрирует жизненный цикл суммы на
      реальном примере — месячная рутина (НДФЛ/зарплата/взносы) твёрдая, а **аванс по УСН
      за 9 месяцев** формируется: в середине квартала состояние `process` («В процессе»,
      «Считаем нарастающим итогом — итог к 28 октября», без числа), после закрытия квартала —
      твёрдое число (104 900 ₽, до 28 октября). Данные сверены с налоговым календарём 2026
      (кассовый метод, аванс за 9 мес. → 28.10.2026, не переносится). Хедер «в августе»
      квартальный аванс не включает — форвардный платёж отделён от месячной рутины.
      Порядок «К уплате»: все просроченные — одной строкой-триггером (счётчик + сумма + стрелка);
      клик открывает дровер справа со списком платежей (`OverdueDrawer` — паттерн из проекта
      «Пульс», пересобран на токенах DS и `DrawerHeader`; Esc/клик по фону закрывают). Затем
      аванс УСН высоким приоритетом (2-я строка), затем ближайшие сроки. Подпись под суммой —
      «Осталось уплатить» (не дублирует таб). Строка платежа вынесена в общий `PaymentRow`.
